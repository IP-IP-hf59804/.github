<h2>一、质量不是真假，是几项指标的组合</h2>
<p>同一个地址在不同平台上表现可能完全不同，所以不存在一个总开关式的质量结论。</p>
<p>更实用的做法是把质量拆成几项可测的指标，分别打分，再看短板在哪。</p>
<p>任何声称能一键判定质量的工具都只能给参考，最终要看自己的业务在真实链路上的表现。</p>
<h2>二、证据链：三层信息要互相印证</h2>
<p>第一层是注册信息，说明地址由谁持有、注册在哪，这层最难伪造。</p>
<p>第二层是路由信息，说明流量实际从哪走，与注册信息冲突时就是异常信号。</p>
<p>第三层是环境信息，包含时区、DNS、语言，三层一致时可信度最高。</p>
<h3>为什么要三层一起看</h3>
<p>单看注册信息会被广播段骗过，单看地理库会被更新延迟骗过，三层叠起来才稳。</p>
<p>实务上把三层写成一行记录，附上查询时间，后面复测就能对比出漂移。</p>

<p>参考线只是筛选门槛，用来快速排除明显不合格的地址，不能替代业务侧验证。</p>
<p>五项里最容易被忽略的是共用度，地址本身很干净但被几十人共用，效果一样会打折。</p>
<h2>四、稳定性要靠连续观测</h2>
<h3>短测看可用性</h3>
<p>两到三天的连续探测能看出断线频率和恢复时间，频繁掉线的地址不适合长期业务。</p>
<h3>长测看漂移</h3>
<p>两周以上的观测能发现地址是否被悄悄更换、归属是否发生变化，这类问题短测看不出来。</p>
<p>观测脚本记录时间戳、出口地址、ASN、延迟四项就够，数据量小但足够定位问题。</p>

<p>这些信号单独出现可能是偶发，短期内重复出现就该考虑换地址。</p>
<p>换地址前先排除自身配置问题，否则换十个地址也解决不了一个错误的时区设置。</p>
<h2>六、一套能照着跑的流程</h2>
<p>第一步查注册与路由，把明显不一致的地址直接排除，不做后续测试。</p>
<p>第二步跑三天短测记录可用率，第三步做并发压测看承载，第四步两周长测看漂移。</p>
<p>四项都过再放量，放量后保留每周一次的抽检，成本不高但能提前发现退化。</p>
<h2>常见问答</h2>
<h3>有没有一个分数能代表质量？</h3>
<p>答：没有统一标准。各家评分模型的权重不同，同一地址可能得到相反结论。建议自己定指标和阈值，用业务数据校准。</p>
<h3>地址被标记过还能恢复吗？</h3>
<p>答：部分情况下会随时间淡化，但取决于标记来源与严重程度。用于关键业务前应先小流量观察，不宜直接放量。</p>
<h3>为什么白天好用晚上变差？</h3>
<p>答：住宅线路在晚高峰拥塞更明显，共享带宽的产品尤其如此。可以对比不同时段的延迟与丢包来确认。</p>
<h3>检测要花很多时间吗？</h3>
<p>答：初次筛查每个地址几分钟，连续观测可以脚本化。真正费时间的是业务侧验证，建议抽样做而不是全量做。</p>
